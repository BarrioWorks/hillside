The following risks remain substantive for the completed overhaul, but do not block selection of C.

- **Forest floors still reveal tile ownership.** In the Salento close-up, the foreground forest sits on a strongly darkened green area with angular transitions. `GroundField.color()` mixes 80% toward `forestFloor` for a fully forest-owned point, and `ground.ts` derives ownership from `tile.kind`. Shared vertex colors can be continuous while the overall pattern still reads as a hex-sized patch. Reassess this after the new forest composition, with attention to broad connected masses rather than merely passing seam tests.
- **Riverbanks are not part of the world-space field.** `material.ts` applies one vegetation gain to green `Surface.soil`; `tiles.ts` builds the banks as constant-color ribbons. Their uniform olive margins remain visible next to changing terrain. This is not a geometry crack. It is a later water/ground integration issue, visible in all three close-ups. Preserve channel continuity when addressing it.
- **Regional atmosphere is only partially established.** M1 regional sun/fill overrides apply in afternoon. Daylight and evening retain shared light colors, with candidate exposure fixed at 1. Bogotá and Cartagena have authored configurations and numerical coverage, but no inspected visual acceptance here. The completed overhaul needs those regions and the other light presets checked before a universal default is chosen.

The implementation review found the following.

- **Determinism and gameplay separation are sound in the inspected path.** `GroundField` samples pure integer-hashed, seeded world coordinates. It does not consume the decoration RNG or gameplay stream. `World` passes `snapshot.seed` into a new field during ground rebuilding. The tests verify repeatability, reversed tile order, and changed seed behavior. Domain rules, building recipes and placement logic are outside the inspected diff.
- **Color conversion is coherent.** Authored OKLCH is converted to linear RGB explicitly, then passed to `setRGB(..., LinearSRGBColorSpace)`. Existing hex colors receive Three.js's conversion once. Gain calculation and shader luminance use linear values. Background hex output goes through `getHexString()`, whose installed implementation defaults to sRGB, and the canvas texture remains tagged sRGB. I found no double gamma conversion or unsupported OKLCH CSS parsing. Gamut mapping lowers chroma for authored colors; field interpolation finally clamps channels. That last clamp is not equivalent to perceptual gamut mapping, but no visible clipping defect was established in these captures.
- **Terrain topology is preserved.** The ground changes replace color evaluation without moving terrain vertices. Legacy fingerprints pass for five seeds, and the candidate geometry comparison preserves position, normal and surface attributes. Shared top-color tests pass for all candidates across four seeds. This is useful evidence for equal-height terrain seams, not a proof that banks, grass lips and every future board share one color field.
- **The shader path uses supported mechanisms.** `onBeforeCompile` still extends `MeshStandardMaterial`; environment grading occurs after vertex color and before the existing patterns. Installed `WebGLPrograms.js` includes defines in its program cache key, so the unchanged custom key does not by itself cause candidate/legacy program reuse. Environment grading survives the low-tier pattern toggle. No added render pass, shadow-radius claim, new shadow filter or unsupported renderer option appears in this diff. Low-tier runtime compilation remains the root's verification responsibility.
- **Geometry cache identity is not expanded by M1.** Environmental gains are uniforms applied to existing cached geometry, while ground colors are rebuilt and the prior ground geometry disposed. Region changes update gains without needing a separate geometry cache per palette. `Lighting` disposes the old background on a preset/region background change. Its background key is sufficient because the candidate selection is fixed for the lifetime of the instance.
- **Shared material state has a bounded current assumption.** Feature flags and gain uniforms are module-global, and `syncDefines()` updates the singleton `worldMaterial`. This fits the current one-world path. An independently created material from `createWorldMaterial()` would not receive later define toggles, and simultaneous worlds could not carry independent gains. I found no current production caller requiring either behavior. Treat this as an ownership constraint if preview galleries or parallel worlds are added, not a reason to redesign M1.
- **Production still defaults to legacy.** Missing or unrecognized environment queries resolve to legacy with Neutral. Candidate grading is opt-in. A valid explicit tone-mapping query can also change legacy, as documented. The focused legacy fingerprints and lighting assertions pass.
- **Architectural preservation is qualified correctly.** Facade plaster, paint, brick, concrete, roofs, wood and metal do not enter the new environment grading branches. Building geometry and the palette file are unchanged. Environmental light necessarily changes lit building pixels. Stone retaining structures, stair supports and the Medellín starter forecourt do receive the stone gain, and access paving receives the paving gain. This is compatible with grading infrastructure, but it would be inaccurate to claim every architectural pixel or every supporting surface is unchanged.
